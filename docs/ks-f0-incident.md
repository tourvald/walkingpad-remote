# KS-F0 Incident — рабочий документ расследования

*Стоп не завершается (state=1, creep 0.2–0.8 км/ч) + переключение units на мили.*
*Обновлено: 2026-06-11. Статус: P0, активный. Владелец: см. STATUS.md.*

---

## 1. Симптомы

- Две дорожки KingSmith **KS-F0 / F0** не останавливаются полностью: после Stop полотно ползёт на минимальной скорости (0.2–0.3 км/ч по KSFIT; 0.3–0.8 в наших логах).
- KSFIT виснет на **«Device Stopping»**; родной RF-пульт тоже не останавливает; power-off на 1–3 дня не помогает.
- Ранее на одной дорожке: KSFIT «Equipment is preparing, please try again later» при GO.
- KSFIT начал показывать скорость в **милях** (раньше — км/ч).

## 3. Аудит нашего BLE-слоя (закрыт)

- Один-единственный `writeValue` (BluetoothManager), все команды через одну очередь.
- Единственный конструктор WalkingPad-кадров жёстко шьёт тип **`0xA2` (runtime)** — приложение **структурно неспособно** отправить `0xA6` (`set_pref_*` / NVRAM-запись).
- Вся поверхность: stop(speed-0) / set-speed / mode-manual / mode-standby / start + queryParams (read). На connect ничего не пишется.
- CRC корректен (сверен с ph4/QWalkingPad). Телеметрия пишет каждый write: `command_write` (hex, char_uuid, `command_source`), `controller_state`/`controller_manual_mode` в каждой строке (коммит `03db316`).

**Вывод:** записать persistent-настройку по документированному протоколу наше приложение не могло.

## 4. Протокольная карта KS-F0

**Кадры:** `F7 <type> … <crc> FD`, crc = sum(bytes[1:-2]) & 0xFF. Ответы начинаются с `F8`. Кадры с неверным CRC контроллер игнорирует.

**Runtime `0xA2`** (формат `F7 A2 cmd value crc FD`):
| cmd | value | Смысл |
|---|---|---|
| 0x00 | 0x00 | GET_STATUS (poll; QZ шлёт 1 Гц как noOp) |
| 0x01 | speed×10 | set speed; **0 = «стоп» в ph4-традиции** (но см. §8) |
| 0x02 | 0/1/2 | режим: AUTO / MANUAL («unlock» в QZ) / STANDBY (sleep) |
| 0x04 | 0x01 | **START/STOP toggle** («start_belt is actually toggle_belt»; у QZ — `start_pause`) |

**Persistent prefs `0xA6`** (формат `F7 A6 key 0 b2 b1 b0 crc FD`, NVRAM):
| key | Параметр | Источники |
|---|---|---|
| 0 | **query** (read-only, ответ = все параметры) | QZ init, QWalkingPad |
| 1 | target/goal | ph4 + QWalkingPad |
| 2 | **cali/regulate** («1=вкл калибровка, 0=выкл, но полотно продолжает ехать») | только QWalkingPad |
| 3 | maxSpeed | ph4 + QWalkingPad |
| 4 | startSpeed | ph4 + QWalkingPad |
| 5 | autoStart/intelligent | ph4 + QWalkingPad |
| 6 | sensitivity (1=high 2=med 3=low) | ph4 + QWalkingPad |
| 7 | display bitmask | ph4 + QWalkingPad |
| 8 | **units** (0=metric 1=imperial) | ph4 + QWalkingPad |
| 9 | childLock | ph4 + QWalkingPad |

Команды «reset to defaults» **нет** ни в одном источнике; откат = записать прежнее значение (поэтому сперва читать).

**Недокументированные** (видны в QZ-init = снифф KSFIT; мы НЕ шлём): `F7 A5 61 …` (handshake/профиль), `F7 B1 …` (похоже на дату/время), `F7 B3 …`. Диалект официального приложения шире известных prefs → поверхность для порчи persistent state больше.

**belt_state (`F8 A2`, байт 2):** 0 = stopped/idle · 1 = running · 5 = standby/sleep · 7, 9 = переходные при старте. QWalkingPad: `padRunning = s != 0 && s != 5`. Наша дорожка зависает в **s=1** → контроллер «считает, что бежит».

## 5. External research — ключевые факты

Источники: [ph4-walkingpad](https://github.com/ph4r05/ph4-walkingpad) (локальный клон), [QWalkingPad](https://github.com/DorianRudolph/QWalkingPad) (независимый RE, Protocol.cpp), [qdomyos-zwift (QZ)](https://github.com/cagnulein/qdomyos-zwift), [KS-Fit-Pro](https://github.com/OskarKozaczka/KS-Fit-Pro), [CodeJawn/walkingpad](https://github.com/CodeJawn/walkingpad), [huserben/walkingpad](https://github.com/huserben/walkingpad), мануалы KingSmith.

1. **KS-F0 маппится на `kingsmithr1protreadmill` в QZ** (диалект R1 Pro); это единственные упоминания F0 в открытом коде (+KS-Fit-Pro, написанный под устройство «KS-F0»).
2. **QZ использует `F7 A2 04 01` как штатный stop/pause toggle** — при requestStop шлёт только его (ни speed-0, ни STANDBY). В трекере QZ нет жалоб на стоп KingSmith.
3. **`speed=0` для F0 может быть не полноценным stop, а снижением до floor** — рабочая гипотеза, согласующаяся с creep 0.3–0.8 и state=1 в наших логах: контроллер ждёт «кнопку» (toggle) для завершения.
4. **`queryParams` (`F7 A6 00 00 00 00 00 A6 FD`) — стандартный read-запрос:** QZ шлёт его при каждом подключении (initData3), QWalkingPad — тоже. Наша Debug-кнопка легитимна.
5. **units-pref существует и persistent** (`0xA6 key 8`, NVRAM контроллера).
6. **Наше приложение не пишет (и не может писать) `0xA6` persistent params.**
7. **Units/mph — открытый и важный тред** (§7): факт переключения произошёл и должен быть объяснён.
8. Никакого публичного отчёта о симптоме «Device Stopping»/creep не найдено — наш инцидент, видимо, первый задокументированный.

## 7. Units / mph — ОТКРЫТЫЙ тред

**Факт:** дорожка работала в км/ч → теперь KSFIT показывает мили, и `queryParams.unit = 1` (imperial) в NVRAM. Изменение произошло и требует объяснения; не закрываем как «display-only» без физического доказательства.

**Что возвращает `queryParams.unit`:** байт 13 ответа `F8 A6`; 0=metric, 1=imperial. На тестовой дорожке = 1.

**Как QZ учитывает unit при отправке speed:** **никак.** `forceSpeedOrIncline`: `speed[3] = qRound(requestSpeed * 10)` — км/ч×10 без какой-либо конверсии; парсинг скорости `packet[3]/10.0` — тоже без конверсии; A6-ответ QZ вообще не парсит; в файле нет ни `mile`, ни `1.60`. Конвертация миль у QZ — только на уровне UI-настройки приложения.

**Косвенные доказательства, что провод = км/ч независимо от unit:**
- QZ годами шлёт км/ч×10 на тысячи KingSmith-пад (включая imperial-сетапы в США) — жалоб на ×1.6 ошибку скорости в трекере нет.
- Наш лог 2: средняя командная скорость рампы 5.2 км/ч × 167 с ≈ 242 м — дорожка отдала 240 м (сходится при км/ч-физике).
- Длина шага: 382 шага / 240 м = 0.63 м/шаг (правдоподобная ходьба); при mph-физике 1.0 м/шаг (неправдоподобно).

**Что это НЕ доказывает:** прошивка F0 могла бы юнит-скейлить и дистанцию (самосогласованность не ловит); закрыть можно только физизмерением.

**План физического доказательства (владелец):**
1. Экран самой дорожки: km/h или MPH?
2. KSFIT: есть ли тумблер units, переключается ли обратно, слушается ли контроллер.
3. Замер: команда «3.0» на 60 с → метка на полотне × длина полотна × обороты: **≈50 м = км/ч**, **≈80 м = mph**.
4. После units→metric (через физическое сервис-меню): повторный queryParams (ждём unit=0) + тот же замер.
5. queryParams со второй (рабочей/залипшей) дорожки → diff.

**Связанный риск:** даже при км/ч-проводе mph-режим мог исказить **записанные значения** prefs (maxSpeed 7.5 — кандидат), а наша телеметрия читает FE01-скорость как км/ч — если бы физика была mph, мы бы систематически занижали реальную скорость в 1.6 раза. На стоп-выводы это не влияет (state=1 — главный сигнал, юнит-независимый).

## 8. Toggle-stop — статус и инженерный комментарий

**Решение владельца:** не внедряем сейчас; возможен позже как controlled experiment. **Не является доказанным фиксом текущей проблемы.**

**Противоречие (зафиксировано):** родной пульт — тоже toggle, и он не останавливает залипшие дорожки; KSFIT (BLE-клиент, чей stop почти наверняка тот же toggle — QZ реплеит его снифф) виснет на «Device Stopping». Значит **toggle по BLE фактически уже пробовался официальным приложением на залипших дорожках и не вывел контроллер из state=1.**

**Инженерное объяснение, когда BLE-toggle мог бы сработать при молчащем пульте:** пульт — отдельный RF-канал (свой приёмник/спаривание); если деградировал приёмник или слетело спаривание, нажатия вообще не доходят до state machine, а BLE-вход работает. Но у нас KSFIT по BLE тоже не останавливает → отказ в самой state machine контроллера, куда сходятся оба канала. **Честный вывод: «не должен сработать на уже залипшем контроллере, но нужен для полной матрицы»** — плюс отдельная ценность: toggle — кандидат на **штатный stop-path** на будущее (возможно, не вводящий контроллер в floor-состояние, в отличие от speed-0).

## 9. Правила безопасности (действуют)

1. **Никаких `0xA6`-записей / `set_pref_*`** до отдельного решения владельца. Только read (`queryParams`).
2. Никаких недокументированных кадров (`A2 03 07`, `A5`, `B1`, `B3`).
3. Никаких тестов скорости с человеком на полотне; рука на сетевом выключателе.
4. Изменения параметров — только через физическое сервис-меню по инструкции производителя, по одному, с фиксацией до/после.
5. Каждый стоп-тест → CSV → `tools/treadmill_analyzer/analyze_stop_sequences.py`.
